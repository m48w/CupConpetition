# VELOCITY CUP 2026 大会運営Webアプリ仕様書

## 1. 概要

本システムは、フットサル大会「VELOCITY CUP 2026」の試合スケジュール、ライブスコア、順位表、トーナメント、管理者操作をブラウザーで確認・操作するための大会運営Webアプリである。

試合データは `TempServerData/matches.json` に保存し、Vite開発サーバーに組み込んだAPI経由で読み書きする。同じサーバーに接続する複数のブラウザー・複数端末間でデータを共有する。

## 2. 技術構成

- UI: React 18
- 言語: TypeScript
- ビルドツール: Vite
- ルーティング: React Router
- データ保存: `TempServerData/matches.json`（Vite 開発サーバーの API 経由）
- スタイリング: CSS
- 開発サーバー: Vite Dev Server（`/api/*` を処理するAPIミドルウェアを内蔵）
- テスト: vitest

ビルドコマンド:

```bash
npm run build
```

## 4. 大会データ仕様

### 4.1 チーム

- グループ数: 8
- グループ識別子: A〜H
- 1グループのチーム数: 5
- 総チーム数: 40

### 4.2 グループステージ

- 1グループあたり10試合。
- 全8グループで80試合。
- 試合IDは `G-{Group}-{番号}` 形式。
- グループ試合はCourt 1〜3に割り当てる。ただしCourt 3は12:15から使用する。
- 開始時刻は2026-09-26 09:00（Asia/Tokyo）から15分刻みで31スロット。12:15より前のスロットは最大2試合（Court 1・2）、12:15以降は最大3試合（Court 1〜3）を割り当てる。

### 4.3 ノックアウト

- Round of 16
- Quarter-finals
- Semi-finals
- Final
- ノックアウト合計15試合。
- 3位決定戦は設けない。
- 試合時間（ハーフタイム込み）:
  - Round of 16: 18分
  - Quarter-finals（ベスト8）・Semi-finals（ベスト4）: 7分ハーフ・ハーフタイム1分の計15分
  - Final: 10分ハーフ・ハーフタイム3分の計23分
- グループステージ終了後、および各ラウンドの間に18分の休憩を空けて開始する。各ラウンドの開始時刻と試合数は4.4を参照。

### 4.4 大会スケジュール

全95試合を 09:00 から連続開催し、19:59 に終了する。09:00〜12:15はCourt 1・2の2コート、12:15以降はCourt 3を加えた3コートを使う。

| ラウンド | 時刻 | 試合数 |
|---|---|---|
| グループステージ | 09:00 〜 16:45（15分×31スロット。12:15より前の13スロットで26試合、以降の18スロットで54試合） | 80 |
| Round of 16 | 17:03 / 17:21 / 17:39（各18分） | 8 |
| Quarter-finals | 18:15 / 18:30（各15分） | 4 |
| Semi-finals | 19:03（15分） | 2 |
| Final | 19:36 〜 19:59（23分） | 1 |

制約は次の3つである。

- 同一コートで試合の時間帯が重ならない。
- 同一チームの試合間隔を15分以上空ける。
- Court 3には12:15より前の試合を入れない。

いずれも `src/features/tournament/schedule.test.ts` で検証している。

### 4.5 試合状態

試合状態は次の4種類。

- `SCHEDULED`: 予定
- `LIVE`: 試合中
- `PAUSED`: 一時停止
- `FINISHED`: 試合終了

### 4.6 試合項目

- 試合ID
- Round
- Group
- Court
- 開始予定時刻
- 試合時間（`durationMinutes`、分単位。グループ戦15分、ノックアウト18分）
- 状態
- ホームチーム
- アウェイチーム
- ホームスコア
- アウェイスコア
- ライブタイマー開始時刻
- 一時停止時の経過秒数

## 9. 管理者仕様

### 9.1 ログイン

- 画面右上のAdmin loginからログイン画面を開く。
- デモ用アクセスキー: `VELOCITY-DEMO-ONLY`
- ログイン成功後、`/admin/setup`へ遷移。
- 認証状態はlocalStorageに保持。
- Exit adminでログアウト。

### 9.2 直接アクセス

未認証で`/admin/setup`へアクセスした場合、管理者パスワード入力画面を表示する。

### 9.3 試合操作

選択した試合の状態（Not started / ● LIVE / Ⅱ PAUSED / ■ Finished）とタイマーを、試合操作の上に大きく表示する。試合選択リストにも、未開始以外の試合には状態を併記する。

管理者は選択した試合に対して以下を実行できる。

- ホーム・アウェイスコアを1点増減。押すたびに即時保存し、全端末へ反映する。未開始の試合では操作できない。
- 操作ボタンは状態に応じて表示を切り替える。

| 現在の状態 | 表示するボタン | 動作 |
|---|---|---|
| `SCHEDULED` | ▶ Start match | `LIVE`にし、タイマーを0から開始する |
| `LIVE` | Ⅱ Pause | `PAUSED`にし、経過時間を保存してタイマーを止める |
| `LIVE` / `PAUSED` | ■ Finish match | `FINISHED`にし、最終の経過時間を保存する |
| `PAUSED` | ▶ Resume | `LIVE`に戻し、止めた時点の続きからタイマーを進める |
| `FINISHED` | なし | — |

### 9.4 大会運営操作

Admin画面の「SUPERADMIN SETUP」には、選択中の試合とは別に大会全体に対する操作がある。

- **Seed knockout teams**: グループステージの順位からRound of 16の対戦相手のみを埋める。試合時刻・Courtは変更しない。
- **Schedule check**: 現在の全試合についてコートの二重予約の有無と最終試合の終了時刻を実際に計算して表示する（例: `ⓘ Schedule check: 95 matches, no court clashes, finishing 19:59.`）。コート重複がある場合は該当する試合IDの組を表示する。
- **↺ Reset all matches**: 全95試合をスコア・タイマー未設定の初期状態に戻す。ボタンを押すと確認メッセージが表示され、「Yes, reset」で実行、「Cancel」で取り消す。通常のリセット手段はこのボタンである（詳細は10章）。

## 10. データ同期仕様

試合データは `TempServerData/matches.json` を唯一の正本とする。ブラウザーはこのファイルを直接読み書きできないため、Vite開発サーバーに組み込んだAPIミドルウェア経由で操作する。

### 10.1 API

| メソッド | パス | 用途 |
|---|---|---|
| `GET` | `/api/state` | 全試合とversionを返す |
| `GET` | `/api/stream` | SSE。接続時に全state、以後は更新のたびに配信 |
| `PATCH` | `/api/matches/:id` | 1試合の部分更新 |
| `PUT` | `/api/matches` | 全置換 |
| `POST` | `/api/reset` | 全試合を未開始へ戻す |

### 10.2 更新の流れ

スコアや状態の編集など、試合単位の操作は `PATCH /api/matches/:id` として送られる。Seed knockout teamsは `PUT /api/matches`、Reset all matchesは `POST /api/reset` を使う。サーバーは該当の試合だけを書き換え、`version` を1つ増やして保存し、接続中の全クライアントへSSEで新しいstateを配信する。SSEで配信するJSONは1行にシリアライズする（複数行にすると、ブラウザーの `EventSource` がパースできないため）。

`PATCH` で変更できるのは `status`、`homeScore`、`awayScore`、タイマー項目、PK戦項目のみである。試合ID、Round、Court、開始予定時刻、対戦チームは変更できない。

存在しない試合IDを指定した場合は `404` で `{"error": "unknown match: ...", "code": "UNKNOWN_MATCH"}` を返す。変更できないフィールドを含めた場合は `400` で `{"error": "field is not patchable: court", "code": "FIELD_NOT_PATCHABLE"}` を返す。リクエストボディがJSONとして解釈できない場合も `400` を返す。`code` はクライアント側でエラー種別を判別するためのものである。

### 10.3 保全

- 書き込みはPromiseチェーンで直列化し、並行更新による取りこぼしを防ぐ。
- 一時ファイルへ書いてから `rename` するため、書き込み中断でファイルが壊れない。
- 起動時に `matches.json` が壊れていた場合、`matches.corrupt-<日時>.json` へ退避して初期データで作り直す。

### 10.4 接続断

サーバーへ接続できない場合、画面上部に切断バナーを表示し、管理操作を無効化する。最後に取得したデータは表示したままにする。SSEはブラウザーが自動的に再接続し、再接続時に全stateを受け取って同期する。

## 11. 非機能・制約

- 試合データは `TempServerData/matches.json` に保存し、Vite開発サーバーが起動している間だけ読み書きできる。サーバーを停止するとAPIも停止する。
- 複数端末・複数ユーザーでの同時編集をサポートする。書き込みはサーバー側で直列化するため取りこぼしは起きないが、同一フィールドを同時に変更した場合は後着信が優先される（明示的なロックや競合解決はない）。
- デモ用アクセスキーはフロントエンドコードに含まれるため、本番運用には不適切。
- 大会本番で利用する場合は、サーバーサイド認証と永続化されたデータベースなど、本番運用に耐える基盤が別途必要である（API・リアルタイム配信は実装済み）。

```

```

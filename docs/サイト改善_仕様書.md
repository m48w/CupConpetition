- **作成日**: 2026-11-02
- **関連文書**: `docs/レビュー書_2026-10-30.md`、`docs/サイト改善_設計書.md`、`docs/仕様書.md`

## 1. 目的

- 大会の参加者（ミャンマー人の選手・代表者・観客）が、スマホで迷わず使えるサイトにする。
- 使わない機能・ページを減らし、大会前と大会当日に必要な情報をすぐ見られるようにする。
- 画面を **英語** と **ミャンマー語** で表示できるようにする。

### 1.1 利用者

| 利用者 | 主な目的 | 主な端末 |
|---|---|---|
| 選手・観客 | 試合の時間・コート、結果、順位を見る | スマホ |
| 代表者 | チーム登録、メンバー登録、大会情報の確認 | スマホ・PC |
| 管理者（Super Admin / SubAdmin） | 試合の運営、登録の管理、お知らせ | PC・iPad |

## 3. 段階1: 整理と使いやすさ

### 3.1 URL暗号化の廃止

- アドレスバーには普通のURLを表示する（例: `/20261220/matches`）。
- `/u/<token>` 形式のURLは新しく作らない。
- 以前の `/u/<token>` のURL（ブックマークやシェア済みのもの）を開いた場合は、元のURLへ **301リダイレクト** する。復号できないトークンは今までどおり404。
- `POST /api/route-token` は廃止する。

### 3.2 下のメニュー（スマホ）

7つから5つにする。

| 順番 | 名前（英語） | 内容 |
|---|---|---|
| 1 | Home | 大会トップ（カウントダウン、お知らせ、大会当日は試合中の試合） |
| 2 | Matches | 全試合の一覧（フィルター付き） |
| 3 | Groups | グループごとの順位表と試合（Groups と Standings をまとめる） |
| 4 | Knockout | 決勝トーナメント |
| 5 | Info | 大会情報（段階3で作る。それまでは Teams） |

- **Teams** は Home の「参加チーム」から開く。PCの左メニューには残す。
- **Live** は大会当日だけ Home の上に表示する（「Live now」）。`/live` のページ自体は残す。
- `/standings` は `/groups` へリダイレクトする。

### 3.3 Groups と Standings の統合

- `/groups` に全グループの順位表を表示する。
- グループを選ぶと（`/groups/:groupId`）、そのグループの順位表と試合一覧を表示する。
- 順位表の列名は省略しない（Played / Won / Drawn / Lost / Goal diff. / Points）。スマホで幅が足りないときは、Played・Goal diff.・Points だけ表示する。

### 3.4 ヘッダー

- 公開ページのヘッダーから **Admin ボタンを外す**。管理者は `/20261220/admin` を直接開く。
- ヘッダーの内容: 大会ロゴ、大会名、**言語切り替え**（段階2）、**Register** ボタン。
- **Register** ボタンはチーム登録ページへ移動する。メンバー登録へは登録ページの中から移動する。
- スマホ（375px）でも重ならず、ボタンの高さは44px以上にする。

### 3.5 大会前の空ページ

試合やチームのデータがまだない場合は、空白ではなく案内を表示する。

| ページ | 条件 | 表示（英語） |
|---|---|---|
| Matches | 試合が0件 | The match schedule will be published soon. |
| Groups | チームが0件 | Groups will be announced after registration closes. |
| Knockout | グループ戦が終わっていない | Knockout teams are decided after the group stage. |
| Live | 試合中の試合がない | No matches are being played right now. |

### 3.6 レビューの残り

- ヘッダーロゴを小さい画像（WebP、128px程度）にする。
- クラブロゴは、表示用に小さくした画像を返す（段階1では幅の上限をCSSで固定し、画像の縮小は設計書の方針に従う）。
- Admin ログイン画面: プレースホルダー「e.g. subadmin1」を消し、入力欄に `<label>` を付ける。
- セキュリティヘッダーを付ける（`X-Content-Type-Options`、`Referrer-Policy`、`X-Frame-Options`、`Content-Security-Policy`）。
- 英語の表現を直す（レビュー書 3.4 の表のとおり）。

## 4. 段階2: 多言語化

### 4.1 対象の言語

| 言語 | コード | 備考 |
|---|---|---|
| 英語 | `en` | **最初に表示する言語** |
| ミャンマー語 | `my` | ユニコードのミャンマー文字（Zawgyi は使わない） |

### 4.2 切り替え

- ヘッダーに `EN | မြန်မာ` の切り替えボタンを置く。全ページで同じ位置。
- 選んだ言語はブラウザに保存し、次に開いたときも同じ言語で表示する。
- 切り替えてもページは移動しない（今のページのまま文字だけ変わる）。

### 4.3 翻訳する範囲

| 範囲 | 翻訳 |
|---|---|
| 公開ページ（Home、Teams、Matches、Groups、Knockout、Live、Info） | する |
| 登録ページ（チーム登録、代表者確認、メンバー登録、完了） | する |
| エラーメッセージ（サーバーからのエラーも含む） | する |
| 日付・時刻の表示 | する（例: 英語 `Sun, 20 Dec 2026`、ミャンマー語は月名・曜日をミャンマー語にする） |
| 管理画面（Admin、Console、登録管理） | **しない**（英語のまま） |
| チーム名・クラブ名・選手名 | しない（登録された文字のまま） |
| お知らせ | 管理者が英語とミャンマー語の両方を入力する（6.2） |

### 4.4 翻訳の進め方

- Claude が英語の文をミャンマー語に訳す。
- ココさんが確認・修正する。翻訳は1つのファイルにまとめ、プログラムを読まなくても直せるようにする。
- ミャンマー語の訳がない文は、英語で表示する（画面が空にならない）。

### 4.5 英語の書き方

- 短い文、やさしい単語を使う（英語が少しわかる人向け）。
- サッカー用語の略語（P、GD、PTS など）は使わない、または説明を付ける。

## 5. 段階3: 大会情報と登録状況

### 5.1 大会情報ページ（Info）

URLは `/20261220/info`。次の項目を表示する。

| 項目 | 内容 |
|---|---|
| Date | 大会の日付 |
| Venue | 会場名、住所、地図（Google マップへのリンク） |
| Getting there | 行き方（電車、駐車場など） |
| Schedule of the day | 受付、開会式、試合開始、表彰式などの時間 |
| Rules | 大会ルール（試合時間、人数、交代、カード、PKなど） |
| What to bring | 持ち物 |
| Contact | 問い合わせ先 |
| FAQ | よくある質問 |

- 英語とミャンマー語の両方を用意する。

決まっている内容（2026-11-03）:

| 項目 | 内容 |
|---|---|
| Date | 2026年12月20日（日） |
| Venue | FUT MESSE 海老江 |
| Address | 〒553-0001 大阪府大阪市福島区海老江８丁目１６（英語表記: 8-16 Ebie, Fukushima-ku, Osaka 553-0001, Japan） |
| Map | https://maps.app.goo.gl/k6uMpg4X18z44hNT9 |
| Time | 9:00〜20:00 |
| Rules | あとで登録する（それまでは「To be announced」） |
| Getting there / What to bring / Contact / FAQ | 未定（「To be announced」） |
- Home の「Tournament rules」の欄は、Info ページへのリンクにする。

### 5.2 登録状況の表示

- Home と チーム登録ページに、登録チーム数を表示する（例: `12 / 40 teams registered`）。
- 定員は **40チーム**。40チームに達したら「Registration is full」と表示し、**受付を止める**（サーバーでも拒否する）。
- チーム登録の締め切りは **2026年12月6日（日）23:59:59 JST**。締め切り後は「Registration is closed」と表示し、受付を止める。
- メンバー登録の締め切り（2026年12月12日（土）23:59:59 JST）も表示する。
- 定員と締め切りは、1回の申請の全チームで判断する。例えば残り2枠のときに3チームの申請があれば、全部を拒否する（一部だけ登録しない）。

## 6. 段階4: マイチーム、お知らせ、CSV出力

### 6.1 マイチーム

- Home で「My team」を1つ選べる。ログインはいらない。選んだチームはブラウザに保存する。
- 選ぶと Home の上に次を表示する。
  - 次の試合（時間、コート、相手）
  - 試合中ならスコア
  - グループの順位
- Matches では「My team only」のフィルターをすぐ使える。
- 選べるのは試合運営用のチーム（グループに入ったチーム）。チームがまだないときは表示しない。

### 6.2 お知らせバナー

- Super Admin が管理画面からお知らせを出せる。
- 項目: 英語の本文、ミャンマー語の本文、種類（Info / Warning）、表示・非表示。
- 公開ページの上にバナーで表示する。WebSocketで、ページを読み込み直さなくてもすぐ表示される。
- 同時に表示するお知らせは最大3件。新しい順。
- 見た人はバナーを閉じられる（そのお知らせだけ、その端末で非表示）。

### 6.3 登録データのCSV出力

- Super Admin の登録管理画面に「Download CSV」ボタンを置く。
- 1行 = 1メンバー（メンバーがいないチームは1行）。列: Club, Team, Representative, Email, Phone, Player, Back number, Registered at。
- Excel で文字化けしないようにする（UTF-8、BOM付き）。
- SubAdmin とログインしていない人は使えない。

## 7. テスト環境

公開前に、皆でテスト（登録、試合の操作など）できるようにする。本番のデータは汚さない。

### 7.1 方針

- 本番とは **別のURL・別のデータ** のテスト環境を作る（Cloudflare Workers の別 Worker）。
  - 本番: `https://velocity-cup.komyat-8mk.workers.dev/`
  - テスト: `https://velocity-cup-staging.komyat-8mk.workers.dev/`（名前は予定）
- テスト環境は本番と同じ画面・同じ機能。データ（Durable Object）だけ別。
- テスト環境の画面の上に「TEST SITE — data will be deleted」の帯を常に表示し、本番とまちがえないようにする。
- テスト環境では、登録の締め切りと定員のチェックを止められる（何回でもテストできるように）。
- 管理者のパスワードは本番と別にする。

### 7.2 本番の `/test/`

- 本番では `/test/` を **公開しない**（404）。サンプルデータの確認はテスト環境で行う。
- テスト環境では `/test/` を開ける。

### 7.3 テストの流れ

1. テスト環境にデプロイする（`npm run deploy:staging`）。
2. 皆にテスト環境のURLを送り、チーム登録・メンバー登録・画面の確認をしてもらう。
3. 見つかった問題を直して、もう一度テスト環境で確認する。
4. 問題がなければ本番にデプロイする（`npm run deploy`）。
5. テスト環境のデータは、必要なら管理画面の「大会の初期化」で消す。

# 設計書: イエローカード・レッドカードの記録

- **文書バージョン**: 1.1.0（実装済み）
- **作成日**: 2026-11-19（あとから整理）
- **関連文書**: `docs/カード記録_仕様書.md`

---

## 1. データ

```sql
CREATE TABLE IF NOT EXISTS match_cards (
  id TEXT PRIMARY KEY,
  match_id TEXT NOT NULL,
  team_id TEXT NOT NULL,
  member_id TEXT,          -- 1.1.0 から新しい記録は必ず登録選手（古いデータは NULL があり得る）
  player_name TEXT,
  back_number INTEGER,
  color TEXT NOT NULL CHECK (color IN ('YELLOW', 'RED')),
  minute INTEGER NOT NULL,
  created_at TEXT NOT NULL,
  source_card_id TEXT      -- 1.1.0: 2枚目のイエローで自動に入れたレッドのとき、元のイエローの id
);
```

- 1.1.0 の移行: 起動時に `PRAGMA table_info(match_cards)` を見て、`source_card_id` が無ければ `ALTER TABLE match_cards ADD COLUMN source_card_id TEXT`。今のデータはそのまま残る。

- 型: `MatchCard`（`sourceCardId?: string | null` を追加）、`CardColor`（`src/types/index.ts`）。`TournamentState.cards` で配信する。

## 2. API（`worker/api.ts`）

| メソッド | パス | 権限 | 内容 |
|---|---|---|---|
| `POST` | `/api/matches/:id/cards` | Super Admin・担当コートの SubAdmin | `{ teamId, memberId, color }`。選手は `resolveScorer` で登録選手か確かめる。`memberId` が `null` なら `400 INVALID_PLAYER` |
| `DELETE` | `/api/cards/:cardId` | 同上 | 削除。`source_card_id` がこの id のカード（自動のレッド）も一緒に消す。無いカードは 404 `UNKNOWN_CARD` |

エラー: 未開始 `400 MATCH_NOT_STARTED`、チームが試合に出ていない・選手が違う `400 INVALID_PLAYER`、色が違う `400 INVALID_CARD`。

## 3. ストア（`worker/store.ts`）

- `addCard`・`removeCard`。分は `goalMinute(elapsedSeconds(match, now))`。
- `addCard`: `player.memberId` が無ければ `INVALID_PLAYER`。YELLOW のとき、同じ試合・同じ `member_id` のイエローがちょうど1枚あれば、同じトランザクションで RED を1行追加する（同じ分・同じ `created_at`、`source_card_id` = 新しいイエローの id）。並びは `created_at, rowid` なのでイエローの次にレッドが来る。
- `removeCard`: `DELETE FROM match_cards WHERE id = ? OR source_card_id = ?`。
- 退場した選手のチェックはしない（カードを出せる）。
- `writeAll` で `clearGoals` のときは `DELETE FROM match_cards`、そうでなければ `pruneCards`。`initialize`・`replaceTeamsAndSchedule` でも全部消す。

## 5. テスト

- `worker/store.test.ts`: 全ステージで記録・削除できる。Unknown player は `INVALID_PLAYER`。2枚目のイエローで自動レッド（同じ分・`sourceCardId`）、3枚目では増えない、2枚目を消すとレッドも消える。
- `worker/api.test.ts`: 記録と削除の API。`memberId: null` は 400。
